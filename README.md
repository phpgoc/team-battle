# 团战管理工具

团战管理工具用于管理两支队伍之间的 1v1 团队赛事。赛事包含第一轮抢分赛、第二轮 KOF，以及在双方各赢下一轮时进行的大将战。访客无需登录即可观看实时赛事和浏览赛事历史。

## 管理员操作

### 超级管理员

超级管理员负责创建账号和赛事，也可以处理任意赛事的管理操作。

1. 在“账号管理”中创建选手账号。账号只有超级管理员和选手两种身份；赛事管理员是在创建赛事时从选手账号中指定的。
2. 在“创建赛事”中填写赛事名称和开始时间，选择赛事管理员、参赛选手以及各项赛事规则。赛事管理员可以暂不指定，由超级管理员继续负责；参赛选手也可以留到之后添加。
3. 两队人数可以不同，总人数为 6–12 人。可以将选手固定到 A 队或 B 队，其余选手由系统随机分队。所有参赛者都可以随机分队。
4. 完成选手分组前，设置第一轮和 KOF 的抢分目标、首轮排阵方式以及 KOF 首发方式。默认第一轮抢 4 分、KOF 抢 5 分；KOF 首发默认随机，也可以由队长安排。
5. 大将战规则可以在首场对局开始前设置，包括多胜、多败、特殊候选组及其概率。未分配的概率由完全随机兜底。抽选时间可以在赛事进行中继续调整。

超级管理员可以指定或更换队长、安排选手、录入或修正比赛结果、确认赛事结束，也可以修改任意未结束赛事的合法设置。赛事确认结束后不能再编辑。

### 赛事管理员

赛事管理员由超级管理员在具体赛事中指定。进入该赛事的看板后，使用右上角的赛事设置和操作入口管理比赛。超级管理员拥有相同权限，并可以覆盖赛事管理员的操作。

赛事开始前，管理员可以补充选手、完成分队、指定队长或不设队长，并准备第一轮排阵。开始比赛后，第一轮、KOF 和大将战规则均锁定；抽选时间仍可调整。比赛结束时，管理员需要确认赛事结果。确认前可以修正错误录入，确认后比赛记录不可修改。

赛事背景可以在赛事看板中切换，切换结果会同步给其他观看者。已结束赛事不能再切换背景。

### 选手

选手登录后可以查看自己参加的赛事和账号设置。赛事开始前，选手可以为本队队长投票；某位候选人的票数达到本队人数的一半时，该选手自动成为队长。管理员也可以直接指定队长，队伍可以没有队长。

第一轮排阵由队长手动安排，或按赛事设置由系统随机产生。KOF 中胜者留场、败者换人：有队长时由队长安排本队下一位；没有队长时，选手可以自行报名。报名成功后，下一位置不会提前公开，上一局结束后才会显示对阵。目标分高于本队人数且全队都输过一次时，系统会随机安排复活选手。

登录用户可以修改自己的登录名、密码、显示名、头像和分类。修改密码需要输入两次新密码，不需要旧密码。普通选手的显示名和头像每 7 天可以修改一次；超级管理员没有此限制。每个账号只允许一处登录。

## 观赛与赛事历史

首页展示已结束赛事，支持按赛事名称和比赛开始日期筛选，并可分页浏览。点击赛事可以打开独立的比赛看板。正在进行的赛事可以从首页或赛事链接进入，看板会自动更新比赛进度。

实时赛事和历史赛事均使用适合全屏观赛的独立页面。点击选手姓名可以查看其总胜负、按分类统计的胜负以及大将战胜负。登录用户也可以在账号设置中查看自己的相同战绩。

看板提供简体中文、English 和 한국어三种界面语言。语言切换会保留当前所在页面。

## 编译与部署

项目使用 Go 编译。编译后即可运行单个服务程序：

```text
go build -o team-battle .
./team-battle
```

Windows PowerShell 下可使用：

```powershell
go build -o team-battle.exe .
.\team-battle.exe
```

程序首次启动时会自动创建数据库、数据目录和超级管理员账号：

- 数据库默认位于当前工作目录的 `runtime/team-battle.sqlite`，程序会自动创建 `runtime` 目录。
- 首次创建的超级管理员账号为 `admin`，初始密码为 `test1234`。请登录后尽快修改密码。
- 用户头像和分类图片保存在数据库中；赛事背景图片保存在数据库旁的 `uploads/backgrounds` 目录中。部署时请保留数据库及该目录中的运行数据。

启动参数均为可选项：

- `--db`：数据库文件路径，默认 `./runtime/team-battle.sqlite`。
- `--host`：HTTP 监听地址，默认 `localhost`。
- `--port`：HTTP 监听端口，默认 `9527`。

例如：

```text
./team-battle --db ./runtime/league.sqlite --host 0.0.0.0 --port 9527
```

程序只提供 HTTP，不内置 TLS。需要 HTTPS 时，请通过 Nginx 等反向代理配置证书并转发到服务监听端口。

### 试用数据

仓库附带 `test.sqlite`，包含测试账号、历史赛事、不同阶段的实时赛事和演示背景。测试账号的密码均为 `test1234`：超级管理员账号是 `admin`，选手账号是 `2` 到 `10`。可使用独立端口启动试用数据：

```text
./team-battle --db ./test.sqlite --port 9528
```

试用数据库仅用于体验和演示。实际部署时请使用默认数据库或指定新的数据库文件。
